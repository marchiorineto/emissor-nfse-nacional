## Planning Decisions (Claude's discretion, recorded)

- **Code split:** `api.js` (fetch wrapper), `form.js` (pure helpers, no DOM), `emitir.js` (DOM). `dom.js` arrives in
  03-03 with its first second user.
- **Field ids without names:** every field has `id="field-<key>"` and no `name`, so a form control can never shadow a
  form property (`form.id`, `form.name`) and a native submit sends nothing.
- **Already issued (D-09):** detected from the answer, never with a GET pre-check: `isAlreadyIssued` compares the
  nota's `updatedAt` with the request start on the server clock (Date header minus the elapsed time measured in the
  browser). The creation time is wrong for this because a rejected or pending nota keeps it when it is resent and issued
  (RESEARCH Pitfall 3). The notice itself is wired in 03-03.
- **Taker validation (D-03):** CPF and CNPJ check digits are validated in the browser (the API only counts digits); a
  CNPJ with letters cannot be issued by this API yet, and the help text says so (RESEARCH Pitfall 11).
- **Competence (D-05):** validateForm refuses a date after today in Brasília (rule E0015 would reject it).
- **Reversibility:** every choice here is reversible (page markup, module split, URL query names on one page).

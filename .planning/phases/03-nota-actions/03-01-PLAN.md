`sendDps`. Internal behavior only; the `/v1` contract does not change.

government wait, a second tab and a second device, which the browser's disabled button cannot see.

assumption.

request, so any state inside createNotas is per request.

Lock shape to implement (RESEARCH Pattern 4, probe-verified on 2026-11-21): a module-level
`WeakMap<Repo, Map<string, Promise<unknown>>>`; `serialized(repo, id, fn)` takes the map for `repo` (creating it),
chains `fn` after the current tail for `id` with the tail's rejection swallowed (`.catch(() => undefined).then(fn)`),
stores the new tail, deletes the map entry in a `finally` only when the stored tail is still its own, and returns the
run promise (so the caller sees fn's own result or rejection).

Test doubles: src/app.test.ts has `env`, `ok(status, json)`, `TOKEN`, `auth` and `createMemoryRepo`; its module-level
`gov` answers instantly, so the new case builds its own slow gov and calls `createApp` directly. src/notas.test.ts has
`config`, `request(overrides)`, `createFakeGov()` (sent[], sendScript, canceled) and `createMemoryRepo`.

## Planning Decisions

- **Where the lock lives (D-18):** module level in `src/notas.ts`, keyed by the `repo` object, because `createNotas` is
  rebuilt per request. `issue` and `cancel` share one key space per id, so an issue and a cancel of the same id also run
  one after the other.
- **What is not serialized:** `pdf`, `get` and `list` stay concurrent (read-only). `markReplaced` saving the old nota of
  a replacement is not locked under the old id; replacement from the panel is out of scope (PANEL-06).
- **Reversibility:** reversible. The lock is an implementation detail behind the unchanged `Notas` interface.

## Flagged Assumptions (not silently dropped)

- **A5 (research):** one Node process owns the SQLite file (one container, as README and Dockerfile describe). With
  several processes on one file the in-process lock would not serialize; a database reservation would be needed. The
  README gains a note (Task 2). Accepted by the user with D-18.
- **EDGE ACT-01, ACT-02 (edge probe: unclassified, unresolved):** the deterministic edge probe could not classify
  these requirements. The `[edge ...]` truths in must_haves were written by hand from RESEARCH Pitfall 1 and the probe
  log; they are flagged for review, not probe-verified.

## Planning Decisions (Claude's discretion, recorded)

- **One cancel UI (D-11):** the row link and the footer link both set `&cancelar` in the hash; sync() turns the flag
  into `view.cancel` and re-renders the nota already loaded, so there is no second form and no refetch.
- **No form element:** the reason UI is a section with type="button" buttons, so no implicit submission exists; this
  also keeps the smoke's Fechar selector unambiguous (RESEARCH anti-pattern).
- **Placement:** the cancel section is the first block of the dialog body (after the notes), so the government's
  "Erros no cancelamento" box of a 422 appears right under it.
- **Default reason:** code 2, the same default the API uses. Suggestions: 1 'Nota emitida com erro; será emitida
  novamente corrigida', 2 'Serviço não prestado; valor devolvido ao cliente', 9 'Cancelamento solicitado pelo emitente'.
- **Row update:** re-render one row by id (`tr.dataset.id`) found by comparing dataset values, never through a CSS
  selector built from the id.
- **Reversibility:** reversible (client UI; the cancel route is unchanged).

<assumption_delta_decision>
- **Signal:** assumption-delta scan, kind `pluralization` (term "also", ROADMAP Phase 1 success criterion 4): `/v1`
  gains a second credential, the admin session cookie, next to the Bearer API token.
- **Primary noun now:** "authenticated caller": a request authenticated by one of two credentials, the Bearer API token
  (external systems, checked first, D-19) or the admin session cookie (browser, plus CSRF on writes, D-16, D-18).
- **Decision: promote.** The Bearer-only middleware is replaced by a single `requireAuth` that names the general
  concept; the Bearer check is its first branch, unchanged in behaviour, and the cookie is its second. Not
  add-alongside: a second middleware stacked beside the token one would let a later route be wired to only one of them.
- **Invariant test (accepted, cheap):** Task 2 enumerates `app.routes` and asserts every non-GET/HEAD `/v1` route refuses a
  cookie request without CSRF; it turns red if a later phase adds a write route outside `requireAuth` or narrows CSRF to
  POST only.
</assumption_delta_decision>

## Planning Decisions (Claude's discretion, recorded)

- CSRF applies to every method except GET and HEAD (D-18 asks for POST today and for PUT, PATCH or DELETE if added; this
  needs no later change).
- A CSRF failure answers **403** `{ error: 'invalid csrf token' }`, distinct from the 401 of a missing or expired session
  (D-05), so the Phase 2 script can tell "log in again" from "reload the page" (RESEARCH Pitfall 8).
- An `Authorization` header that is present but empty stays on the Bearer path and gets 401, as today (D-19).
- Startup notice: off, on, or a warning when `ADMIN_PASSWORD` is non-empty but not a valid hash (logins then fail closed).

## Flagged Assumptions (edge probe: unclassified, surfaced, not silently dropped)

- **AUTH-05 (unclassified):** "write calls (POST) also need a CSRF token" is assumed to cover every method other than
  GET and HEAD, with the token sent as `X-CSRF-Token` and taken from the page's `csrf-token` meta; "external systems keep
  using the Bearer token unchanged" is assumed to mean identical status codes and bodies whenever `Authorization` is
  present, proven by the untouched `src/app.test.ts`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (cookie) → /v1 and /health | A second credential now reaches the API; writes must prove same-origin intent |
| external system (Bearer) → /v1 | Must behave exactly as before whatever cookies arrive |
| operator → README and startup log | Wrong guidance would leave sessions alive or the panel misconfigured |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-25 | Tampering | cross-site writes to /v1 with the cookie | high | mitigate | SameSite=Strict plus X-CSRF-Token = HMAC bound to the session id, compared in constant time, on every method but GET and HEAD (Task 1; invariant test in Task 2) |
| T-01-26 | Elevation of privilege | wrong Bearer falling back to the cookie | high | mitigate | When Authorization is present only the Bearer branch runs (D-19); tests for wrong and empty Bearer next to a valid cookie (Task 2) |
| T-01-27 | Elevation of privilege | cookie honoured while the panel is off | high | mitigate | `admin` is undefined when ADMIN_PASSWORD is empty, so the cookie branch cannot run (AUTH-01; Task 2 test) |
| T-01-28 | Information disclosure | distinct 401 bodies revealing cookie state | low | mitigate | One body, `{ error: 'unauthorized' }`, for missing, empty, expired, tampered and other-hash cookies; only the CSRF failure differs (403) |
| T-01-29 | Elevation of privilege | session reach equal to the token | low | accept | D-18 gives the session the same reach as the Bearer token by design; the panel is single-admin |
| T-01-30 | Repudiation / Spoofing | operator believes sessions ended without a restart | medium | mitigate | Script message (plan 01-01), README section and startup notice all say a restart is needed (D-02) |
| T-01-31 | Tampering | malformed ADMIN_PASSWORD silently weakening the panel | medium | mitigate | verifyPassword fails closed on an unparseable hash and the startup notice warns (Task 2, Task 3) |
| T-01-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package (RESEARCH Package Legitimacy Audit: none); nothing to gate |

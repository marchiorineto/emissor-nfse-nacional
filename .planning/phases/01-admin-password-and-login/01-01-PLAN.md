## Planning Decisions (Claude's discretion, recorded)

- Hash format `scrypt:<N>:<r>:<p>:<saltB64url>:<hashB64url>`: no `$`, space, quote, `#` or `=`, so it is safe unquoted in
  `.env`, in Docker Compose (which interpolates `$`) and in `String.replace` (RESEARCH Pattern 1, Pitfall 3).
- scrypt parameters N=65536, r=8, p=2, key length 32, 16-byte salt, `maxmem` 256 MiB (one of OWASP's equivalent scrypt
  settings; ~0.37 s and 64 MiB per hash, measured in RESEARCH). Node's default 32 MiB `maxmem` would reject these.
- No-TTY input: two lines on piped stdin (`printf '%s\n%s\n' "$SENHA" "$SENHA" | pnpm run admin-password`). Never an
  environment variable: the package script loads `.env` first, so `ADMIN_PASSWORD` in the environment is the OLD hash
  (RESEARCH Pitfall 5).
- Length is counted in code points; the password is never trimmed; NFKC is applied inside the single derive helper, so
  hashing and verifying cannot diverge (RESEARCH assumption A1).
- `setVar` in the new script rewrites every `ADMIN_PASSWORD=` line (global flag): Node's `.env` parser keeps the LAST
  value of a repeated name (verified with `util.parseEnv`), so replacing only the first line would leave the old hash in
  force.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator terminal or pipe → script | The plaintext password crosses here; it must end in scrypt only |
| script → .env file | The only persistent store; other local users and other parsers (Node, Docker) read it |

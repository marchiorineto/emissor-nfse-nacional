## Planning Decisions (Claude's discretion, recorded)

- Modules: `src/session.ts` (cookie, CSRF, HTTPS detection, constant-time compare), `src/admin.ts` (routes and pages),
  `src/password.ts` from plan 01-01. All testable through `createApp` deps.
- Cookie name `nfse_admin` (no `__Host-` prefix: it would force Secure and break plain-HTTP local installs); value
  `<id>.<expSeconds>.<sig>` in base64url, signed with HMAC-SHA256 under `sessionKey = HMAC(ADMIN_PASSWORD, 'admin-session')`.
- HTTPS detection (D-06): request URL `https:`, or `PUBLIC_URL` starting with `https://`, or `X-Forwarded-Proto`
  containing `https`; any one signal sets Secure.
- Failed login answers **401** (D-14 left 401 or 200 open).
- A malformed non-empty `ADMIN_PASSWORD` keeps the routes registered and every login fails closed (verifyPassword gives
  false); plan 01-04 adds the startup warning. A whitespace-only value counts as empty (trimmed in `envFrom`).
- Phase 1 pages carry no JavaScript (login and logout are form posts).

## Flagged Assumptions (edge probe: unclassified, surfaced, not silently dropped)

- **PASS-04 (unclassified):** "existing admin sessions stop working" is assumed to hold after the server restarts with
  the new hash (D-02); the running process keeps its startup key until then. Verified by building two apps with
  different hashes.
- **AUTH-01 (unclassified):** "empty" includes whitespace-only; "answer 404" means Hono's default 404 for unregistered
  paths (same body and content type as any unknown path). `/v1` behaviour when empty is verified in plan 01-04.
- **AUTH-02 (unclassified):** "land on /admin" means a 303 redirect to `/admin` after a classic form POST (D-14).
- **AUTH-06 (unclassified):** "ends the session" means the browser's cookie is cleared (Max-Age=0); a copied cookie stays
  valid until its 12 h expiry, an accepted risk recorded in code (D-04).
